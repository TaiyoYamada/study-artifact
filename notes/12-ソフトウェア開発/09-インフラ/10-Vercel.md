# Vercel

フロントエンド向けのホスティング・配信プラットフォーム。
Next.js の開発元でもある。

## 特徴

| 特徴 | 内容 |
| --- | --- |
| **Git 連携** | push すると自動でビルド・デプロイ |
| **プレビュー環境** | ブランチ／PR ごとに固有の URL |
| エッジ配信 | 世界中の拠点から |
| サーバレス関数 | API を同じリポジトリに置ける |
| 即時ロールバック | 過去のデプロイに戻せる |

**PR ごとのプレビュー URL** が実務で効く。
レビューする人が実際に触って確認できる。

## 対応する方式

| 方式 | 対応 |
| --- | --- |
| SSG | ○ |
| SSR | ○（サーバレス関数として） |
| ISR | ○ |
| エッジ関数 | ○ |

[[ソフトウェア開発/Web/フロントエンド|レンダリング方式]]を
ページ単位で選べる。

## 類似のサービス

| サービス | 特徴 |
| --- | --- |
| **Cloudflare Pages / Workers** | エッジ実行に強い。転送量無制限のプラン |
| Netlify | 先行者。同様の体験 |
| GitHub Pages | 静的のみ。無料 |
| Firebase Hosting | Google の周辺サービスと統合 |

**このノートサイトは Cloudflare Pages に置いている。**
完全な静的サイトなので、
サーバレス関数もエッジ実行も要らず、
ファイルを配るだけで済む。

## 判断の観点

| 観点 | 内容 |
| --- | --- |
| 静的だけで足りるか | 足りるなら選択肢が広い |
| **転送量の課金** | 大量配信では差が大きい |
| ビルド時間の上限 | 大規模サイトで問題になる |
| ベンダー固有機能 | 移行のしやすさ |

Next.js の一部機能は Vercel 上で最も良く動くため、
**フレームワークとプラットフォームの結び付き**が
実質的なロックインになりうる点は意識しておく。
